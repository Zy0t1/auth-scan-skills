# B 类检查清单：权限控制缺陷

> 根因：已认证主体越权访问资源，或权限检查机制缺失、检查逻辑本身有缺陷。
> 对应 CVE 簇：权限控制缺陷 47 条（86 条中数量最多，Jenkins 插件生态为重灾区）。
> 两种形态：**授权检查缺失**（端点上根本没有检查）与**检查有缺陷**（检查存在但可绕过）。

## B1. 权限检查存在性与粒度（CWE-862 / 863 / 285 / 1220）

- [ ] 对照入口台账：每个端点是否**显式**调用权限检查，还是依赖继承链/框架默认行为？
- [ ] 权限检查用的是精确权限还是最低门槛权限？警惕最低权限（`Overall/Read`、`View/Read`、`Job/Read`、登录即可）即可到达的敏感操作：
  - 查看凭据明文（CVE-2025-67636：View/Read 看密码明文）
  - 枚举凭据 ID / 验证凭据有效性（CVE-2018-1000109、CVE-2020-2285、CVE-2026-48926）
  - 修改插件/系统配置（CVE-2018-1000106、CVE-2020-2282）
  - 执行审批 / promotion（CVE-2018-1000114）
  - 触发后台任务 / 取消他人队列（CVE-2017-2611、CVE-2026-53438）
- [ ] "能否执行操作"与"操作目标是否在授权范围内"是否**分别**检查？（见 B3）
- [ ] 权限不足时的失败路径：是否校验失败后仍继续执行？（CWE-280/274/636 Fail Open）
- [ ] 特权 API 调用前是否鉴权？（CWE-648）

## B2. 权限继承陷阱（CWE-266 / 267 / 268 / 842）

- [ ] 层级权限模型中，子操作默认继承的父权限范围是否过宽？创建权限是否意外包含覆盖已存在对象的能力？（CVE-2017-2599：Item/Create 覆盖他人 Item）
- [ ] 多角色叠加后是否获得未预期权限？（CWE-268 权限链）
- [ ] 新建用户/服务账户的默认角色与默认组是什么？是否默认入高权限组？（CWE-842/1188）
- [ ] 插件/扩展注册端点时继承的默认权限是什么？

## B3. 越权与归属校验 / IDOR（CWE-639 / 283 / 99 / 566）

- [ ] 对象级操作是否校验**对象归属**，而非只校验全局权限？
  - 触发他人管道（GitLab CVE-2024-8970）
  - 覆盖他人 Item（CVE-2017-2599）
  - 访问他人视图配置（CVE-2024-43045）
  - 读取他人构建产物、日志、工单
- [ ] 资源 ID 是否用户可控且未校验归属（直接改 ID 访问他人资源）？
- [ ] SQL/查询中主键直接来自请求参数且未加归属条件？（CWE-566）
- [ ] 资源创建时 owner 字段赋值是否正确？（CWE-708）
- [ ] 批量查询/导出接口是否按调用者权限过滤结果集？（CWE-202/639）

## B4. 权限重用与 Token 作用域（CWE-1259 / 1270）

- [ ] Token/PAT 每次使用时是否校验 scope / audience / 绑定资源，还是只在签发时校验一次？（GitLab PAT scope 逃逸，CVE-2024-8114）
- [ ] OIDC/OAuth 令牌能否跨服务重用？（aud 不校验 → 见 check-authn.md A2）
- [ ] 凭据是否隔离存储：不同 Task / Agent / 账户的凭据是否共享文件系统 / 命名空间？（Tekton 系统级 Git Token 存共享文件系统，CVE-2026-40161）
- [ ] fork 构建 / 外部触发构建能否读到原仓库 Secret？（Travis CI CVE-2021-41077）
- [ ] CI 缓存、工作区在高低权限构建间是否隔离？（GitLab 缓存竞态窃取高权限凭据，CVE-2024-9183）

## B5. 权限委托与功能提权（CWE-441 / 269 / 250）

系统代替用户执行高权限操作时，委托必须伴随约束：

- [ ] 备份 / 导入导出 / 合规框架 / 诊断包等**系统功能**以高权限运行时，触发者权限校验是否充分？（GoCD 备份提权 CVE-2024-56320/56321；GitLab 导入导出提权 CVE-2016-4340）
- [ ] 委托操作的目标范围是否限制在触发者授权范围内，还是透传服务账户全量权限？（混淆副手 CWE-441）
- [ ] CI 引擎持有的部署服务账户是否按命名空间/项目收敛？用户操作是否透传 cluster-admin 级权限？
- [ ] Operator / Controller 类组件的调谐循环是否校验对象创建者的授权范围？（Flux CD CVE-2026-23990）
- [ ] Runner / 构建容器是否以 root / 特权模式运行？（CWE-250/272）

## B6. Agent ↔ Controller 边界（CWE-862 / 863 / 441）

把 Agent 视为**已被攻陷的半可信域**，评估它能从 Controller 拿到什么：

- [ ] Agent 认证通过后，后续请求的身份是否来自服务端绑定的会话，还是客户端自报 `agent_id`？（Woodpecker CVE-2026-50141）
- [ ] Agent 发起的文件/RPC 操作是否限制在该 Agent **自己的**构建目录/资源范围？（Jenkins CVE-2021-21697：任意 Agent 读写他人构建目录；CVE-2021-21685：mkdirs 无检查）
- [ ] 复制/创建 Agent 的权限是否泄露已有 Agent 的密钥？（Jenkins CVE-2025-31721：Computer/Create 复制 Agent 窃取密钥）
- [ ] Agent → Controller 的每个请求是否独立鉴权，还是认证一次后续全信？

## B7. 多租户与跨命名空间（CWE-283 / 863 / 1220）

- [ ] 团队/命名空间/项目标识是否从服务端认证会话提取？客户端传入的 `team_name`、`namespace`、`project` 参数是否直接参与授权决策？（Concourse CVE-2022-31683）
- [ ] 跨命名空间/跨租户操作是否校验**目标域**：不只查"能否发起操作"，还查"目标是否在授权域内"？（ArgoCD sharding RBAC 绕过 CVE-2023-22736；Image Updater CVE-2026-6388）
- [ ] 分片（sharding）、多副本、缓存路径下的 RBAC 检查是否与单实例路径一致？**条件分支是校验遗漏高发点**。
- [ ] 已认证用户通过路径遍历访问授权范围外资源？（ArgoCD CVE-2022-24730/24731；Tekton CVE-2026-33211）

## B8. 证明义务（每条候选必须回答）

1. 攻击者的前置权限是什么（未认证 / 任意登录 / Read 级 / 特定角色）？
2. 被越权访问的资源归属谁？归属校验在哪一行本应发生？
3. 越权后能读什么 / 改什么 / 执行什么？是否构成提权闭环？
