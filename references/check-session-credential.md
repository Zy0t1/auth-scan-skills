# C + D 类检查清单：会话管理缺陷 与 凭据密钥管理

## C 类：会话管理缺陷

> 根因：会话标识与生命周期管理缺陷，导致会话被固定、劫持或失效不及时。
> 对应 CVE 簇：其他类型中的会话固定 2 条 + Web 场景通用。

### C1. 会话固定与轮换（CWE-384）

- [ ] 认证成功后是否**废弃旧会话并签发新会话 ID**（`invalidateSession()` / `regenerate`）？
  - 判定方法：对比登录前后会话 ID，相同即会话固定。（Jenkins SAML CVE-2018-1000602、GitHub Auth CVE-2019-1003019）
- [ ] 匿名阶段发放的会话 ID 是否在认证后被提升为认证态而未更换？

### C2. 会话过期与失效（CWE-613）

- [ ] 登出后会话/令牌是否真的失效（服务端吊销），还是仅前端清 Cookie？
- [ ] 会话超时是否过长？CI 控制台、长期 API Token 有无有效期？（CVE-2017-1000354：CLI 缓存身份长期有效）
- [ ] Token 刷新时是否重新校验权限，还是只要未过期就放行？
- [ ] 密码修改 / 权限变更后，旧会话是否全部吊销？

### C3. Cookie 安全属性（CWE-614 / 1004 / 1275 / 315 / 539 / 565）

- [ ] 敏感 Cookie 是否设置 `Secure`（仅 HTTPS）+ `HttpOnly`（防 JS 读取）+ `SameSite`（Lax/Strict）？
- [ ] Cookie 中是否明文存放 Token、角色、权限等敏感信息？（CWE-315）
- [ ] Cookie 中的角色/权限字段是否签名防篡改？（CWE-565：未签名 Cookie 直接存角色 → 改 Cookie 提权）
- [ ] "记住我"持久化 Cookie 是否内含可恢复凭据？（CWE-539）

## D 类：凭据与密钥管理

> 根因：密码、Token、密钥在生成、存储、传输、展示、作用域环节的缺陷。
> 对应 CVE 簇：凭据与密钥泄露 9 条（日志泄露、Diff 泄露、明文存储、显示未掩码、隔离失效）。
> 审计思路：**跟踪一条凭据的生命周期**——生成 → 存储 → 传输 → 使用 → 展示 → 销毁，逐环节检查。

### D1. 存储（CWE-256 / 257 / 260 / 259 / 798 / 321 / 312）

- [ ] 配置文件（`.env`、`config.xml`、`*.properties`、`*.yml`）中是否有明文凭据？（Jenkins CVE-2026-53442：POST config.xml 的 secret 未加密存储）
- [ ] 源码中是否硬编码密码 / Token / API Key / 加密密钥 / salt / IV？（CWE-798/321/547）
- [ ] 密码是否用可逆加密代替哈希？（CWE-257）哈希算法是否为 bcrypt/argon2/PBKDF2 而非单次 MD5/SHA？（CWE-916/328）
- [ ] 出厂/示例默认密钥是否未更换？（CWE-1394）
- [ ] 密钥文件、凭据目录的文件系统权限是否过宽？（CWE-732/276）

### D2. 传输（CWE-319 / 598 / 523）

- [ ] 凭据是否经 HTTP 明文传输（含内部服务间调用）？
- [ ] Token 是否放在 URL query string？→ 会被日志、Referer、浏览器历史泄露（CWE-598）。
- [ ] 构建脚本中凭据是否作为命令行参数传递？→ 进入进程列表与构建日志（TeamCity CVE-2025-54538）。

### D3. 展示与泄露面（CWE-532 / 201 / 209 / 1230）

逐一面检查凭据是否掩码：

| 面 | 检查点 | 代表 CVE |
| --- | --- | --- |
| 构建日志 | 密码/Token 自动掩码；**截断导致脱敏失效**（长凭据截断后绕过掩码匹配） | GitHub Actions CVE-2025-31479 |
| 异常输出 | 错误分支、堆栈、连接失败信息中的凭据 | CVE-2025-31479（异常路径泄露 GITHUB_TOKEN） |
| Diff 视图 | 配置差异展示中 Secret 掩码；**故意提交无效 Secret 触发错误 Diff 泄露** | ArgoCD CVE-2025-23216 / CVE-2026-42880 / CVE-2026-43824 |
| UI / API 响应 | 凭据字段明文返回 | Jenkins CVE-2026-33004、ArgoCD CVE-2025-55190 |
| 调试代码 | debug 模式输出凭据 | CWE-215 |
| 元数据 | 云元数据服务、响应头泄露 Token | CWE-1230 |

- [ ] 掩码逻辑是否与读取权限匹配：能读日志/diff/配置的权限级别 vs 凭据敏感级别？
- [ ] 掩码是黑名单（匹配已知 secret 值）还是白名单？截断、编码、变形后掩码是否仍生效？

### D4. 作用域与隔离（CWE-1259 / 1270 / 1188）

- [ ] CI Token 权限是否过宽可跨项目？OAuth token 有无 scope 限制？
- [ ] 系统级 Token 是否存于共享文件系统 / 共享 emptyDir，被有 TaskRun 权限的用户窃取？（Tekton CVE-2026-40161）
- [ ] Secret 是否跨账户 / 跨 fork 共享？（Travis CI CVE-2021-41077）
- [ ] 资源初始化默认值是否安全（默认匿名可访问 = CWE-1188）？

### D5. 证明义务（每条候选必须回答）

1. 凭据从哪来（哪个 Secret/配置项），明文出现在哪个面（日志/响应/文件/Diff）？
2. 读取这个面需要什么权限？与凭据本身的敏感级别是否匹配？
3. 拿到凭据后能做什么（横向移动目标）？
